# Официальный контекст задачи

Этот файл содержит только подтверждённые сведения из официального ТЗ.

## Задача

По фотографии этикетки найти точную карточку вина в каталоге «Своё Вино».

## Основные данные и ограничения ТЗ

- Каталог содержит примерно 1500–2000 позиций.
- Для каждой позиции есть одна эталонная фотография.
- В каталоге много near-duplicates.
- Основные различия могут быть в годе, сезоне и категории.
- Пользовательские фотографии делаются в реальных условиях.
- Есть публичный и приватный наборы полевых фотографий.
- CV-компонент обязателен.
- OCR допустим как дополнительный сигнал.
- Организаторы рекомендуют обратить внимание на нормализацию изображения.
- Целевая доля совпадений — 90–100%.
- Целевой SLA — до 3 секунд.
- Сервис запускается локально.
- Нативное мобильное приложение не требуется; нужен mobile-first web.
- Разрешены внешние API и open/open-weight модели.
- SigLIP 2 — рекомендуемый ориентир для CV, но не обязательная финальная модель.

## Контракт проверки

Проверочный `participant_test.sh` отправляет изображение как multipart-поле
`image` на `POST /v1/eval/predict`. Сервис должен вернуть Top-1 `slug`:

```json
{"slug":"wine-slug"}
```

Runner также умеет читать ответ в виде массива `[{"slug":"wine-slug"}]`.
Для совместимости проекта сохранён дополнительный `POST /api/predict`, который
принимает изображение как сырое тело запроса.

Проверочный скрипт организатора сравнивает `slug` с закрытой разметкой.

## Критерии оценки

- достоверность поиска — 50/100;
- post-search функция — 20/100;
- архитектура — 15/100;
- дизайн — 10/100;
- скорость — 5/100.
