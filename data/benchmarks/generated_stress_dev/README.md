# generated_stress_dev

Infrastructure-only generative stress benchmark. The plan contains
**150** products × **4** scenarios =
**600** pending generations. No image API is connected
and no images are generated by this repository.

## External generation contract

For each row in `generation_manifest.csv`, use the attached
`reference_image` and prompt, then write the result to:

`data/benchmarks/generated_stress_dev/generated_raw/<output_filename>`

Do not rename files or change `generation_id`. The generation plan is not yet a
scored benchmark. Every output must pass importer validation and manual review.

## AITUNNEL pilot

The repository includes `scripts/generate_stress_aitunnel.py`. It uses the
documented [AITUNNEL image-edit endpoint](https://aitunnel.ru/docs/images)
`https://api.aitunnel.ru/v1/images/generations` with JSON fields
`model`, `prompt`, `input_references`, `quality`, `size`, and `output_format`.
The local reference is sent as a base64 data-URI.
The default model is `gpt-image-2.5-sunburst`, with `quality=low` and
`size=1024x1024`. The documented successful response is
`data[0].b64_json`; URL responses are also accepted if returned by the provider.

The credential must exist only as `AITUNNEL_API_KEY` in the environment. First
inspect the exact 20-request pilot without calling the API:

```bash
.venv/bin/python scripts/generate_stress_aitunnel.py --pilot-products 5 --dry-run
```

After checking that output, run the pilot explicitly:

```bash
.venv/bin/python scripts/generate_stress_aitunnel.py --pilot-products 5
```

On Windows PowerShell, the masked-key wrapper can be used instead:

```powershell
.\scripts\run_stress_aitunnel.ps1
```

It runs one product × four scenarios by default, passes the key only to the
child WSL process, then clears it. It cannot select the full 600-row plan.

For a cheaper comparison pilot, select the supported `gpt-image-1-mini` model
and a separate output directory so the current successful outputs remain
untouched:

```powershell
.\scripts\run_stress_aitunnel.ps1 `
  -Model gpt-image-1-mini `
  -GeneratedDir data/benchmarks/generated_stress_dev/generated_raw_gpt_image_1_mini
```

Import that comparison run into separate review artifacts:

```bash
.venv/bin/python scripts/import_generated_stress.py \
  --generated-dir data/benchmarks/generated_stress_dev/generated_raw_gpt_image_1_mini \
  --review-csv data/benchmarks/generated_stress_dev/review_gpt_image_1_mini.csv \
  --review-html data/benchmarks/generated_stress_dev/review_gpt_image_1_mini.html
```

The command never changes this plan. It writes generated files under
`generated_raw/` and runtime artifacts under `generation_runs/<run_id>/`.
`requests.csv` and `summary.json` contain request status, retries, latency and
provider-reported usage/cost when present. If a valid output already exists it
is skipped; `--overwrite` is required to replace it. `--all` is the explicit
future full-plan option and must not be used for the pilot.

## Workflow

```text
generation_manifest.csv
  → external generation into generated_raw/
  → .venv/bin/python scripts/import_generated_stress.py
  → edit review.csv: review_status=accepted/rejected/pending
  → .venv/bin/python scripts/build_generated_stress_benchmark.py
  → .venv/bin/python scripts/run_siglip2_baseline.py --benchmark generated_stress_dev
  → .venv/bin/python scripts/evaluate_benchmark.py --benchmark generated_stress_dev --predictions <run>/predictions.csv
```

`pending` and `rejected` rows can never enter `manifest.csv`. Generated images
must not be used for training/fine-tuning while this benchmark is frozen.
