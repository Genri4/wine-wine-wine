## Demo для проверяющих

Основной сценарий установки, передачи assets, запуска и API/UI smoke check
описан в [`web/README.md`](web/README.md). Архитектурные границы и ограничения
метрик — в [`ARCHITECTURE.md`](ARCHITECTURE.md).

Чистый GitHub clone пока не самодостаточен: изображения каталога, LoRA
checkpoint и согласованные кэши не входят в Git. Перед демонстрацией на другой
машине нужно отдельно передать согласованный архив, распаковать его в корень
клона и получить успешный результат:

```bash
python scripts/check_demo_assets.py
```

Для этой передачи уже собран локальный архив
`artifacts/demo_runtime_assets_20260929.tar.gz` (411.3 MiB; SHA-256
`0b29a840c27845feabe3ed5902346b2be3cee70ee649586dcdbcacfe6f41cb8d`). Он
игнорируется Git и обычный clone его не получает. Если архив опубликован как
asset публичного GitHub Release, `scripts/setup_demo.ps1 -ReleaseTag <tag>`
скачает его, проверит SHA-256, распакует и выполнит preflight через WSL.
Инструкция находится в [`web/README.md`](web/README.md). До публикации Release
архив нужно передавать отдельно.
Проверяющему также нужен заранее загруженный SigLIP2 snapshot в Hugging Face
cache; первый запуск PaddleOCR требует интернет-доступа для получения моделей.
Установочный скрипт не устанавливает Python/ML-зависимости и не скачивает эти
модельные кэши; настройте их по инструкции запуска. Передача проектного архива
без этих модельных условий сама по себе не гарантирует старт.

## Что считать подтверждённым

- API проверки: `POST /api/predict` возвращает `{"slug":"wine-slug"}`.
- Есть датированный локальный прогон на 100 каталоговых reference images:
  p95 1,117 ms, p99 1,237 ms, max 1,484 ms на RTX 4060 при serial warm
  нагрузке; точные ограничения записаны в
  [`reports/runtime_latency_sla_100_20260926_000314.md`](reports/runtime_latency_sla_100_20260926_000314.md).
- Отчёт UI/API от 26.09.2026 описывает 29 UI-сценариев и API-ошибки:
  [`reports/product_ui_functional_test_20260926.md`](reports/product_ui_functional_test_20260926.md).
- Эти результаты не являются обещанием latency на любом устройстве или
  accuracy на закрытом тесте организаторов.
- Поступившие 100 полевых фото ещё требуют ручной разметки slug/no-match;
  публичная accuracy-метрика на них не заявляется.
- Match for You — простая оценка по коллекции пользователя, а не обученная
  модель рекомендаций. UI desktop-only; коллекция хранится в localStorage.

## Что проверить перед коммитом/публикацией

Ничего не добавлено в index автоматически. В рабочем дереве есть изменения и
новые файлы из предыдущих шагов разработки; перед коммитом вручную сверьте:

```bash
git status --short
git diff --check
git diff --stat
```

Затем проверьте staged file list (`git diff --cached --name-status`) и
убедитесь, что туда не попали `artifacts/`, `data/new_data/`, прикреплённый
PDF, локальные credentials или пользовательские review exports.

До публичного push владелец проекта должен решить:

1. Можно ли публиковать исходный код, каталоговые метаданные, изображения и
   любые benchmark assets для выбранной аудитории. Право на картинки не
   следует выводить из того, что URL был публичным.
2. Каким приватным каналом передать demo assets, если GitHub не должен их
   содержать.
3. Какую лицензию проекта выбрать. `LICENSE` сейчас отсутствует, поэтому
   права повторного использования кода явно не заданы.
4. Будет ли репозиторий public или private; убедиться, что все staged файлы
   допустимы для выбранной видимости.

## Команды проверяющего

После установки зависимостей и передачи проектных assets проверяющий может
исполнить:

```bash
python scripts/check_demo_assets.py
.venv/bin/python scripts/serve_smart_retry.py
```

Во втором терминале выполнить API smoke checks из `web/README.md`, открыть
`http://127.0.0.1:8765/web/` и пройти ручной пользовательский сценарий. Для
Python regression suite:

```bash
.venv/bin/python -m pytest -q -k 'not BaselineReproductionTests'
```

Полный исходный regression suite в ходе подготовки этих README/architecture
изменений не запускался. Исторические результаты 334 passed / 2 deselected и
29 UI-сценариев относятся к прогону 26.09.2026, а не к текущему клону;
смотрите точный состав проверки в отчёте перед тем, как повторять это число.
