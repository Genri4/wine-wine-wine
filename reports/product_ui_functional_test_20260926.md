# Функциональная проверка web app — 26.09.2026

## Результат

- Браузерный прогон: **29 из 29 сценариев пройдены** в отдельном headless Chrome с временным профилем. Основная коллекция и localStorage пользователя не затрагивались.
- Python regression suite: **334 passed, 2 deselected**, 3 предупреждения sklearn. Исключены два baseline reproduction теста, которые повторно загружают pretrained encoder и ранее зависали при чтении модели.
- `node --check web/app.js`: пройден.
- Файл каталога: HTTP 200, 2 103 записи.

## Проверенные пользовательские сценарии

- Загрузка фото и браузерная проверка изображения: неподдерживаемый тип, низкое разрешение, размытие и повреждённый файл.
- Все подсказки Smart Retry: glare, blur, distance, barcode, year, resolution, unreadable, image_too_large, front_label и uncertain.
- Две неуверенные попытки подряд переводят на экран отсутствия точного совпадения; повторная загрузка включает соответствующую кнопку.
- Карточка успешного распознавания и переход к внешней карточке каталога.
- Коллекция: добавление, отмена, закрытие, изменение статуса, обязательный рейтинг 1–5, группы «Хочу попробовать» и «Уже пробовал(а)», сохранение после перезагрузки, удаление и пустое состояние.
- Match for You: фильтр по одному и нескольким признакам, исключение уже распознанной бутылки и выдача ближайших вариантов при частичном совпадении.
- Compare: очередь первой бутылки, отмена очереди, защита от повтора, сравнение двух карточек и сброс.

Для UI-проверок ответ `/api/recognize` подменялся на браузерной границе, чтобы отдельно и быстро пройти каждый экран. Загрузка каталожных фото, клиентская проверка их качества, коллекция и Match for You работали с локальными файлами и реальным каталогом.

### Latency и готовность runtime

- Первый 100-запросный latency-батч был прерван и не считается метрикой: после одного клиентского таймаута последовали ответы HTTP 503. Неверные процентили удалены из отчёта и сохранены как диагностика: [прерванный замер](runtime_latency_aborted_20260925.md).
- Причина: PaddleOCR получал изображение с длинной стороной 4096 px; один эталон размером 3581×5371 обрабатывался сервером около 21,7 s. Для OCR теперь используется ограниченная копия до 1600 px. Энкодер, SIFT, веса и правила слияния продолжают работать на прежнем полноразмерном/замороженном пути.
- Повтор того же большого эталона: HTTP 200 за 2,748 s, точный slug, 2 согласованных сигнала и 6 OCR-линий.
- Два валидных последовательных прогона одного набора из 100 различных изображений после startup warm-up: в обоих 100/100 HTTP 200 и 100/100 ответов быстрее 3 s. Первый: p95 **1,405 ms**, p99 **1,659 ms**, максимум **1,869 ms**. Повтор с проверкой возвращённых slug: p50 **304 ms**, p90 **1,005 ms**, p95 **1,117 ms**, p99 **1,237 ms**, максимум **1,484 ms**.
- Проверка на точных каталоговых эталонах: 97 точных ответов `found`, 3 ответа `retry`, 0 неверных `found`. Из-за OCR downscale изменился входной размер OCR для крупных изображений; этот прогон ограничивает регрессию на эталонах, но не заменяет проверку пользовательских фото.
- Измерение serial/warm на локальном RTX 4060. Оно подтверждает p95 для этой выборки после startup, но не покрывает конкуренцию запросов или распределение реальных пользовательских фото. Новый датасет пока не размечен для такой проверки.
- Полный существующий regression suite после изменения: **334 passed, 2 deselected**, 3 прежних предупреждения sklearn. Исключены два теста `BaselineReproductionTests`, повторно загружающие pretrained encoder и ранее зависавшие при чтении модели.
- Воспроизводимые замеры: [первый проход](runtime_latency_sla_100_20260926_000126.md) и [повтор с точными slug](runtime_latency_sla_100_20260926_000314.md), [CSV по каждому запросу](runtime_latency_sla_100_20260926_000314.csv), [JSON](runtime_latency_sla_100_20260926_000314.json); скрипт: [benchmark_runtime_latency.py](../scripts/benchmark_runtime_latency.py).

- Health отражает `ready`/`busy` и длительность запроса. Параллельный POST получает HTTP 503 с `Retry-After: 1`, не встаёт в очередь.
- Startup прогревает три эталона до открытия порта. Статика ограничена `/web/`, manifest CSV и reference images; корень, `context`, `artifacts` и traversal-пути отвечают 404.
- Реальный `/api/predict` вернул контракт `{"slug":"zb-vajn-spumante-bryut-beloe"}`. В headless Chrome проверены успешный scan, состояние UI при HTTP 503 и 12-секундный timeout с доступной кнопкой повтора.

## Изменения после проверки

- Сброс Compare очищает и скрытые карточки предыдущего сравнения.
- Обработчик закрытия диалога коллекции сохраняет черновик, если окно уже открыли повторно до прихода отложенного события `close`.
- Локальный API ограничивает параллельный inference, отдаёт duration/phase diagnostics, корректно отвечает на malformed `/api/predict`, а web-клиент имеет timeout и руководство восстановления при зависшем GPU-запросе.
